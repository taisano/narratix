# Chart Advisor「相談から入る」推薦フロー実装指示書

> 出典：Tai さんからの指示書（2026-09-24、19〜25章は同日の追記）。本文は受け取ったままを残す。
> **注意：9章の3つのレシピは、1つの相談例に対する例示。** 相談文とレシピの紐づけロジック（分類・順位付け）は今後さらに洗練させる前提で扱う。
> 末尾の「実装メモ」は Claude が追記した、実装に向けた整理。

## 1. 目的

ユーザーがチャート種類を指定せず、自然文の相談から開始した場合に、AIが相談内容を理解し、あらかじめ整備された推薦データベースから適切な「伝え方の切り口」を提案する。

本機能の目的は、多数のチャートを見せることではない。ユーザーが伝えたいことを整理し、目的に合う単一チャート、チャート＋テーブル、または複数チャートの組み合わせを、最大3案に絞って提示することである。

## 2. 基本方針

### 2.1 AIの役割

AIは次の処理だけを担当する。

1. ユーザーの相談文を理解する。
2. 相談内容を所定の分析軸・目的・問いに構造化する。
3. 推薦データベースから条件に合うレシピを検索する。
4. 最大3案を優先順位付きで提示する。
5. 各案について「何が分かるか」「なぜ適しているか」「何が見えにくいか」を説明する。

### 2.2 AIが担当しない処理

AIは次の処理を行わない。

- データ入力後の再分析
- 入力データや生成済みチャートの閲覧・評価
- データに基づく結論や示唆の生成
- 実データを見たうえでの再推薦
- チャート品質の自動採点
- 数値や傾向の推測

AIの呼び出しは、原則として相談内容を解析して切り口を提案する最初の1回だけとする。

## 3. 対象となる入口

### 3.1 相談から入る

ユーザーが自然文で、伝えたい内容、利用場面、対象期間などを入力する。

例：

> 海外5地域の売上（2021〜2025年）で、どこが成長しているかを経営会議で伝えたい。

この入口では、データ入力画面へ進む前に「切り口の提案」ステップを挿入する。

### 3.2 目的またはチャートから入る

ユーザーが「推移」「比較」「構成」などの目的、または特定のチャートを選択して開始した場合は、原則として切り口提案を省略できる。

## 4. 画面フロー

```text
相談を入力
  ↓
AIが相談内容を構造化
  ↓
推薦データベースから候補レシピを検索
  ↓
最大3つの「伝え方の切り口」を提示
  ↓
ユーザーが1案を選ぶ
  または
ユーザーが「3案とも作る」を選ぶ
  ↓
共通データを入力
  ↓
入力データをルールベースで検証
  ↓
選択したレシピに従ってチャート／テーブルを生成
  ↓
ユーザーが手動で調整・出力
```

重要：データ入力後にAIへ戻るループは設けない。

## 5. 「切り口」の定義

切り口はチャート名ではなく、次の要素をまとめた推薦レシピである。

- 答えたい問い
- 伝達の狙い
- メインの可視化
- 補助となる可視化またはテーブル
- 推奨レイアウト
- 必要なデータ形式
- 向いている利用場面
- 見えにくくなる情報・注意点

例：

```text
切り口：成長の軌跡と速さを見る
問い：継続して伸びている地域はどこか
構成：推移チャート＋CAGRテーブル
強み：途中経過と成長率を同時に伝えられる
注意点：地域数が多いと線が混み合う
```

## 6. AIが相談文から抽出する項目

AIは相談文を、最低限次の項目へ構造化する。

| 項目 | 内容 | 例 |
|---|---|---|
| `primary_goal` | 主な分析目的 | `TREND`、`COMPARISON`、`COMPOSITION`、`CONTRIBUTION`、`RELATIONSHIP`、`EVALUATION` |
| `business_question` | ユーザーが答えたい問い | どの地域が成長しているか |
| `audience` | 想定読者・利用場面 | 経営会議 |
| `time_scope` | 時系列の有無・期間 | 2021〜2025年 |
| `comparison_dimension` | 比較対象 | 地域 |
| `measure` | 指標 | 売上 |
| `decision_context` | 判断につなげる必要性 | 注視すべき地域を判断したい |
| `needs_exact_values` | 正確な数値表示の必要性 | `true` / `false` / `unknown` |
| `needs_size_context` | 規模感を示す必要性 | `true` / `false` / `unknown` |
| `needs_rate_context` | 成長率・変化率を示す必要性 | `true` / `false` / `unknown` |
| `confidence` | 解釈の確信度 | 0〜1 |

相談文にない情報は推測で確定せず、`unknown` として扱う。

## 7. AI出力仕様

AIは画面文言を自由生成する前に、次の構造化形式を返す。

```json
{
  "consultation_summary": "海外5地域の売上成長を経営会議で説明したい",
  "interpreted_question": "継続的な成長、成長率、規模の違いをどう伝えるか",
  "classification": {
    "primary_goal": "TREND",
    "audience": "EXECUTIVE_MEETING",
    "time_scope": "2021-2025",
    "comparison_dimension": "REGION",
    "measure": "SALES",
    "needs_exact_values": true,
    "needs_size_context": true,
    "needs_rate_context": true
  },
  "recommendations": [
    {
      "recipe_id": "TREND_CAGR_TABLE",
      "rank": 1,
      "reason_codes": ["TIME_SERIES", "RATE_REQUIRED", "EXECUTIVE_USE"]
    },
    {
      "recipe_id": "SIZE_MIX_CAGR",
      "rank": 2,
      "reason_codes": ["SIZE_REQUIRED", "MIX_CHANGE", "RATE_REQUIRED"]
    },
    {
      "recipe_id": "START_END_CAGR",
      "rank": 3,
      "reason_codes": ["START_END_COMPARISON", "IMPACT", "RATE_REQUIRED"]
    }
  ]
}
```

チャート構成、説明文、注意点、必要データは、AIが新しく発明するのではなく、`recipe_id` を使って推薦データベースから取得する。

## 8. 推薦データベース仕様

各推薦レシピは最低限、次の項目を持つ。

| フィールド | 内容 |
|---|---|
| `recipe_id` | 一意のレシピID |
| `name` | 切り口名 |
| `supported_goals` | 対応する分析目的 |
| `question_patterns` | 対応する問い・キーワード・意味分類 |
| `audience_tags` | 経営会議、営業会議、レポートなど |
| `primary_visual` | メイン可視化 |
| `supporting_visual` | 補助チャートまたはテーブル。不要なら `null` |
| `composition_type` | `SINGLE_CHART`、`CHART_TABLE`、`TWO_CHARTS` |
| `required_schema` | 必要なデータ構造 |
| `required_fields` | 時間、地域、値などの必須フィールド |
| `optional_fields` | 目標値、成長率などの任意フィールド |
| `derived_metrics` | CAGR、差分、構成比など、システムが計算する項目 |
| `strength_text` | 何が分かるか |
| `limitation_text` | 何が見えにくいか |
| `coach_reason_text` | なぜ推薦するか |
| `priority_rules` | 優先順位を上げる条件 |
| `exclusion_rules` | 推薦対象外とする条件 |
| `default_settings` | ラベル、並び順、色などの初期設定 |
| `status` | `ACTIVE`、`DRAFT`、`DISABLED` |

## 9. 今回の相談に対する推薦レシピ例

### 9.1 推薦1：成長の軌跡と速さを見る

| 項目 | 内容 |
|---|---|
| レシピID | `TREND_CAGR_TABLE` |
| 答える問い | 継続して伸びている地域はどこか |
| メイン | 地域別の推移チャート |
| 補助 | 地域別CAGRテーブル |
| 構成 | `CHART_TABLE` |
| 強み | 途中経過と成長率を同時に伝えられる |
| 注意点 | 地域数が多いと線が混み合う。CAGRだけでは実額差が分からない |
| 必要データ | 年、地域、売上 |
| 派生計算 | CAGR |

推奨説明文：

> 推移だけでは、伸びている方向は見えても、成長の速さを正確に比較しにくい可能性があります。推移チャートにCAGRテーブルを組み合わせることで、成長の継続性と速さを分けて伝えられます。

### 9.2 推薦2：市場全体の拡大と構成変化を見る

| 項目 | 内容 |
|---|---|
| レシピID | `SIZE_MIX_CAGR` |
| 答える問い | 海外売上全体の成長を、どの地域が支えているか |
| メイン | 2021年・2025年の絶対値積み上げ棒 |
| 補助 | 地域別CAGR |
| 構成 | `CHART_TABLE` または `TWO_CHARTS` |
| 強み | 全体規模と地域別内訳の変化を同時に伝えられる |
| 注意点 | 小さいセグメントは読みにくい。地域数が多い場合は不向き |
| 必要データ | 年、地域、売上 |
| 派生計算 | CAGR、構成比 |

重要：規模感を伝える場合は、100%積み上げではなく絶対値の積み上げを使用する。100%積み上げは、総額の大きさではなく構成比の変化を主題にする場合のみ使用する。

### 9.3 推薦3：開始年と終了年の変化を強調する

| 項目 | 内容 |
|---|---|
| レシピID | `START_END_CAGR` |
| 答える問い | 5年間で、どの地域がどれだけ変わったか |
| メイン | 地域別の2021年・2025年ペア棒 |
| 補助 | 地域別CAGRテキスト |
| 構成 | `SINGLE_CHART` |
| 強み | 開始値と終了値の差が明確で、変化のインパクトを短時間で伝えられる |
| 注意点 | 途中年の変動、一時的な落ち込み、回復などは見えない |
| 必要データ | 年、地域、売上 |
| 派生計算 | 絶対差、増減率、CAGR |

## 10. 推薦順位の決定方法

推薦順位は、AIの自由判断だけに依存させない。AIが抽出した分類項目と、推薦データベースのルールを使って決定する。

例：

```text
基本適合点
  分析目的が一致                 +40
  必要データ構造が一致           +20
  利用場面が一致                 +10
  成長率が必要                   +10
  規模感が必要                   +10
  正確な値が必要                 +10

減点
  相談内容と異なる目的           -40
  必須データが相談上存在しない   -20
  読み取り負荷が高い             -10
```

AIは分類と候補抽出を支援するが、最終順位は設定可能なルールで再現できることが望ましい。

## 11. 提案画面の表示要件

### 11.1 表示数

- 最大3案とする。
- 推薦1案を最上段に表示する。
- 2案目・3案目は「他のアングル」として表示する。
- 適切な候補が2案しかない場合は、無理に3案目を作らない。

### 11.2 各案に表示する内容

- 切り口名
- 答えられる問い
- チャート／テーブルの組み合わせ
- 推薦理由
- 強み
- 注意点
- 必要なデータの形
- 選択ボタン

サンプル画像は具体的な国名、数値、結論を使わず、構成を示す抽象的な図にする。データ入力前に、実際の結果に見えるサンプルを表示しない。

## 12. ユーザー操作

### 12.1 1案を選ぶ

ユーザーが選択した1つのレシピを保存し、データ入力後にそのレシピだけを生成する。

### 12.2 3案とも作る

「3案とも作る」は提供可能とする。ただし、次の動作とする。

- 3案で共通のデータを1回だけ入力する。
- AIによる再分析は行わない。
- 各レシピの必須条件をルールベースで検証する。
- 条件を満たすレシピをすべて生成する。
- 条件を満たさないレシピは生成せず、不足項目を定型文で表示する。
- 生成後の並び順は、初回推薦時の順位を維持する。
- AIが生成結果を見て再順位付けすることはない。

ボタン文言は「全部作る」よりも、動作が明確な次の表現を推奨する。

> 共通データで3案を作る

## 13. データ入力後の処理

データ入力後は、AIではなくアプリケーションロジックで処理する。

### 13.1 データ検証

- 必須列の有無
- 日付・年の形式
- 数値列の妥当性
- 欠損値
- 重複行
- 比較対象数
- チャートごとの上限件数
- CAGR計算に必要な開始年・終了年

### 13.2 派生値の計算

- CAGR
- 絶対差
- 増減率
- 構成比
- 合計
- ランキング

計算式はアプリケーション側で固定し、AIに計算させない。

### 13.3 不適合時の処理

例：CAGRに必要な開始年または終了年がない場合

```text
CAGRを計算するには、開始年と終了年の両方のデータが必要です。
不足：2021年の売上
```

エラー文は定型化し、AIを呼び出さない。

## 14. コスト管理要件

- 相談フローにおけるAI呼び出しは原則1回。
- 同じ相談文・同じ分類結果に対する推薦結果はキャッシュ可能にする。
- レシピ説明文はデータベースに保存し、毎回生成しない。
- データ検証、計算、チャート生成、エラー表示にはAIを使用しない。
- 目的・チャートから開始した場合は、AI呼び出しを省略する。
- 相談が十分に明確で、ルールだけで分類できる場合は、将来的にAIを使わない経路も検討する。

## 15. AIの禁止事項

AIは以下を出力してはならない。

- 入力前のデータ傾向や結論
- 「中国が最も成長している」など、存在しない数値に基づく表現
- 架空のCAGR、売上、順位
- 推薦データベースに存在しない新しいチャート構成
- 実装対象外の高度な分析
- データ投入後に再評価することを前提とした説明
- 「このデータなら最適」など、未確認データを確認済みと誤認させる表現

データ入力前に使用できる表現は、次のような仮説・可能性・適合性の説明に限定する。

```text
この切り口は、継続的な成長と成長率を一緒に伝えたい場合に適しています。
地域数が多い場合は、線が混み合う可能性があります。
```

```json
{

  "consultation_text": "...",
  "consultation_classification": {},
  "recommended_recipe_ids": [
    "TREND_CAGR_TABLE",

    "START_END_CAGR"

    "TREND_CAGR_TABLE"
  ],

  "ai_used_after_data_input": false

```

推薦ロジックやレシピが更新された場合でも、既存プロジェクトを再現できるように `recommendation_version` を保存する。

## 17. 受入条件

### 17.1 相談理解

- 相談文から分析目的、対象、指標、期間、利用場面を構造化できる。
- 不明な項目を勝手に確定しない。
- AIが数値結果や結論を捏造しない。

### 17.2 推薦

- 推薦データベースに存在するレシピだけを提示する。
- 提示数は最大3案。
- 各案に「問い」「構成」「強み」「注意点」が表示される。
- 具体的なサンプル数値を表示しない。

### 17.3 選択と生成

- 1案選択と複数案選択の両方が可能。
- データは1回の入力で複数案に再利用できる。
- データ投入後にAI APIを呼び出さない。
- 不適合レシピはルールベースで判定される。
- 派生指標は固定ロジックで計算される。

### 17.4 コスト

- 相談開始から出力まで、通常フローのAI呼び出し回数が1回以内である。
- チャート再描画、表示設定変更、エクスポートでAI APIを呼び出さない。

## 18. 実装時の重要な考え方

AIは「答えを出す人」ではなく、相談を正しい分析レシピへ案内する受付・コーチとして扱う。

```text
AI：相談を理解し、適切なレシピを選ぶ
推薦DB：承認済みの伝え方を管理する
アプリ：データを検証・計算・可視化する
ユーザー：どの切り口で伝えるかを決定する
```

この責務分離を崩さないこと。

## 19. 画面全体の左右配置原則

相談画面、切り口提案画面、エディター画面で、左右サイドバーの役割を入れ替えない。

### 19.1 共通レイアウト原則

```text
左側：文脈・現在地・ナビゲーション
中央：比較・プレビュー・成果物
右側：選択・設定・確定操作
```

ユーザーが「操作は右側にある」と学習できるよう、画面遷移後もこの原則を維持する。

### 19.2 切り口提案画面

| エリア | 役割 | 表示内容 |
|---|---|---|
| 左 | 相談の文脈 | 元の相談文、AIが抽出した目的・対象・指標・期間・場面、不明項目 |
| 中央 | 提案の比較 | 推薦案、他のアングル、構成イメージ、強み、見えにくいこと、補完方針 |
| 右 | 選択と次の操作 | 選択中の案、選択解除、1案で進む、共通データで複数案を作る |

左側には、案を選択・確定するボタンを置かない。

### 19.3 エディター画面

| エリア | 役割 | 表示内容 |
|---|---|---|
| 左 | 現在地と設計意図 | スライド一覧、選択中スライド、採用した切り口、この構成で答える問い、補完アドバイス |
| 中央 | 成果物 | スライドプレビュー、必要に応じてデータテーブル |
| 右 | 編集操作 | 保存、チャート変更、表示設定、補完機能、タイトル、出典、言語、出力 |

現在のエディターで左側にある編集操作は、原則として右側へ移動する。左側はスライドナビゲーションと文脈表示に限定する。

データテーブルは中央プレビューの下、または中央エリア内の切替表示に置く。編集設定と混在させない。

### 19.4 左側のアドバイスから直接変更しない

左側に補完アドバイスを表示する場合でも、変更操作そのものは右側で行う。

例：

```text
左側の表示
「構成比に加えて規模も伝える場合は、合計値の表示が有効です」

右側の操作
補完 ＞ 合計値を表示［ON/OFF］
```

左側のアドバイスから右側の該当設定へスクロール・フォーカス移動するリンクは設けてもよい。ただし、左側で設定値を変更しない。

## 20. 「注意点」と補完提案の設計

注意点だけを表示してユーザーに解決を委ねない。各注意点を、次の3種類に分類して扱う。

### 20.1 レシピ標準構成（旧称：必須補完）

「必須補完」という名称は使用しない。選択した切り口が成立するために必要な要素は、補完ではなく、その推薦レシピの標準構成として扱う。

標準構成は、相談内容から直接決定するのではなく、次の2段階で決定する。

```text
AIが相談を構造化する
  ↓
ルールベースで推薦レシピを順位付けする
  ↓
ユーザーがレシピを選択する
  ↓
選択したレシピの標準構成を自動適用する
```

ユーザーは、標準構成に含まれる部品を提案画面で個別に選択しない。

例：

```text
目的：成長の軌跡と速さを伝える
レシピ：推移チャート＋CAGRテーブル
```

この場合、「推移チャートだけでは成長率が分かりにくい」という注意点は、CAGRテーブルによって既に解決済みである。エディターでは両方を初期表示する。

例：

```text
相談：どの地域が成長しているか伝えたい

選択したレシピ：成長の軌跡と速さを見る

自動適用する標準構成：
- 推移チャート
- CAGRテーブル
```

このCAGRテーブルは、ユーザーが補完アドバイスを見て後から追加するものではない。レシピ選択時点で構成に含まれる。

エディターでは標準構成としてONにする。ユーザーによる削除は許可してよいが、削除する場合は次のように影響を表示する。

> CAGRテーブルを外すと、成長の速さを正確に比較しにくくなります。

標準構成の要素を外した場合、画面上の「この構成で答えられる問い」も更新する。

### 20.2 任意補完

同じ入力データから作成でき、ユーザーの伝達意図に応じて追加・削除できる補完。切り口提案画面では選択させず、エディター右側の「補完」セクションで操作できるようにする。

例：

- CAGR表を表示
- 合計値を表示
- 最新年の実額を表示
- 差分ラベルを表示
- 構成比ラベルを表示
- 基準年と最新年を強調
- 注目系列をハイライト

切り口提案画面では、次のように案内する。

> 規模感も伝えたい場合は、エディターで最新年の実額を追加できます。

ここではチェックボックスや設定項目を表示しない。

### 20.3 追加データが必要な補完

現在想定しているデータだけでは作れず、追加の入力項目が必要になる補完。この場合のみ、データ入力前にユーザーへ確認する。

例：

- 目標差を示すための目標値
- 利益性を示すための利益または利益率
- 市場シェアを示すための市場全体値
- 人口当たり指標を示すための人口データ

確認例：

> 売上の成長に加えて収益性も比較しますか？　その場合は利益率の入力が必要です。

追加データを使わない場合でも、元の切り口で先へ進めるようにする。

## 21. 提案画面で選ばせる範囲

提案画面でユーザーが選択するのは「どの問いに答えるか」「どの伝え方を採用するか」までとする。

次の項目は提案画面で選ばせない。

- データラベルのON/OFF
- 合計値の表示
- CAGR表の位置
- 色
- グリッド線
- 軸方向
- 注釈の細かな表示
- テーブルの行列や幅

これらはエディターで調整する。

例外として、補完に追加データが必要な場合だけ、データ入力前に利用有無を確認する。

## 22. 提案カードの文言構造

各提案カードは、ネガティブな注意だけで終わらず、次の順序で表示する。

1. 答える問い
2. 推奨する構成
3. この構成の強み
4. この案だけでは見えにくいこと
5. どのように補えるか

表示例：

```text
答える問い
各地域はどのように推移し、どの程度の速さで成長したか

おすすめの構成
推移チャート＋CAGRテーブル

強み
途中経過と成長率を同時に伝えられます

この案だけでは見えにくいこと
最新年の売上規模の差は、線の位置だけでは比較しにくい場合があります

補い方
エディターで「最新年の実額」を表示すると補えます
```

「注意点」という見出しは、必要に応じて次の表現へ変更する。

- この案だけでは見えにくいこと
- 向いていないケース
- 補完すると伝わること

## 23. エディターの補完セクション

右側の編集サイドバーに、選択したレシピに応じた「補完」セクションを表示する。

### 23.1 表示ルール

- 全チャート共通の補完項目を大量に表示しない。
- 選択したレシピとチャートに関係する項目だけ表示する。
- 推薦レシピに含まれる標準構成は初期状態でONにする。
- 任意補完は、推奨度とともに表示する。
- 追加データが必要な項目は、必要列を明示する。
- AIは使用せず、レシピデータベースの設定から表示する。

### 23.2 表示例

```text
補完

［ON］CAGRテーブル
      成長の速さを正確に比較できます

［OFF］最新年の実額
       規模感も伝えたい場合におすすめ

［OFF］合計値
       全体規模の変化も伝えたい場合におすすめ
```

### 23.3 左側に表示するアドバイス

左側には操作項目ではなく、採用中の設計意図を短く表示する。

```text
今回の伝え方
推移＋CAGR

答える問い
継続して伸びている地域はどこか

補完アドバイス
規模感も伝える場合は、右側の「最新年の実額」を追加できます
```

アドバイスは入力データをAIが評価して生成するものではない。選択したレシピに保存された定型文を表示する。

## 25. 補完に関する受入条件

- 左側と右側の役割が、提案画面とエディターで入れ替わらない。
- 選択・編集・確定操作は右側に置かれる。
- 提案カードの注意点には、可能な場合は必ず補完方法が併記される。
- レシピ標準構成は、選択したレシピからルールベースで自動適用され、ユーザーが個別に再選択しなくても初期表示される。
- 同じデータで可能な任意補完は、提案画面ではなくエディター右側で選択できる。
- 追加データが必要な補完だけ、データ入力前に確認される。
- エディターの補完提案はレシピDBから表示され、AI APIを使用しない。
- 左側のアドバイスは設定変更を行わず、右側の操作場所を案内する。

## 実装メモ（Claude 追記・2026-09-24）

### A. 推薦DBの置き場所
- 最初はコードの中（`src/registry/recipes.ts`）にレシピを置く。チャート・補完パーツ・レイアウトと同じレジストリの一部にすると、「存在しないチャートやレイアウトを指すレシピ」をテストで弾ける（17.2 の「DBにあるレシピだけ」を機械的に保証できる）。
- `recommendation_version` は、レジストリのバージョン（git のタグや日付）と同じにする。
- 開発者以外がレシピを編集したくなったら、その時に Supabase のテーブルに移す。

### B. 1回の AI 呼び出しの中身
- AI には「分類（6章）」と「recipe_id と reason_codes の候補」だけを JSON で返させる（`z.toJSONSchema` で出力の形を固定する）。
- 最終的な順位は 10章の点数ルールをアプリ側で計算して決める。AI の順位は同点のときの参考にとどめる。
- 画面の文言（理由・強み・注意点）はレシピの文言を使い、AI には書かせない。
- API キーはサーバー側だけに置く。AI キーが入るまでは、キーワードで分類するルール版で動かす（14章の「AIを使わない経路」を先に作ることになる）。

### C. 目的・チャートから入る場合との関係（提案）
- 「切り口＝レシピ」は3つの入り口で共通の単位にできる。目的から入る場合は、目的でレシピを絞り込む（AI なし）。チャートから入る場合は、そのチャートをメインに使うレシピを出す。
- こうすると、②の画面は入り口に関係なく「レシピを選ぶ」画面に揃えられる。

### D. 例示の3レシピを作るのに足りない部品
- `TREND_CAGR_TABLE`：折れ線＋CAGR 表（左右2分割のレイアウトと、折れ線に揃えた表）。今の揃えた表は Mekko だけ。
- `SIZE_MIX_CAGR`：2時点だけを使った実額の積み上げ縦棒（今の積み上げ縦棒で年を絞れば作れる）と、CAGR 表。
- `START_END_CAGR`：集合縦棒（ペア棒）と CAGR テキスト。M2-B の残りの作業。

### E. モックへの反映（Chart Advisor 画面モック v7）
- 相談から入ると、②は「推薦1（上段・大きく）＋他のアングル（2案）」になる。各案には問い、構成、推薦理由、強み、注意点、必要なデータ、アプリが計算する値を出す。
- 図は抽象的な構成図にした（国名・数値なし）。
- 左側には「相談の理解」として分類結果を出し、相談文にない項目は「不明」と表示する。
- ボタンは「この N 案で進む」と「共通データで3案を作る」。
- ③では、案ごとにデータのチェック結果を出す（ルールベースの定型文）。見出しはユーザーが自分で書く（データ入力後は AI を使わない）。
