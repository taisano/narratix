# 設計メモ：データと質問から、実データで描いた下書きを出す（改訂2）

2026-10-19、Claude。実装の前の設計案（コードは変えていない）。調査は `docs/data-to-slides-feasibility.md`。
改訂2：ユーザーの「設計修正指示」（7点）を反映した。旧案の `ColumnRoleMap`（特定のチャートに寄った役割）は **破棄**し、時間列・比較対象・表形式を扱える列対応モデルに置き換えた。

## 1. ゴールと基本方針

ユーザーが「質問の文章」と「Excel の表」を入れて「AI 相談」を押すと、次の画面のチャート候補が、**見本データではなくユーザーのデータで描かれて**見える。候補を選んで「スライドを作成」を押すと、編集画面が**データが入った状態**で開く。チャートの種類はユーザーが選ぶ（AI は絞らない）。

基本方針：**AI は列の意味を補助し、数値の転記・計算・描画はコードが行う。** AI には表のセルの値を送らない（§5）。

## 2. ユーザーの流れ

1. 入力：質問の文章と、表の貼り付け（任意）。表が無ければ今までどおり。
2. 「AI 相談」を押す：コードが表を読み、列の特徴を計算する。AI は、質問と列見出し・型などから「各列を何に使うか」を返す（AI の呼び出しは1回）。
3. おすすめの画面：候補のプレビューが、ユーザーのデータで描かれる。各候補に「列の使い方」の1行が付き、直せる。
4. 候補を切り替える：AI は呼ばない。列の使い方を直しても、AI は呼ばない。
5. 「スライドを作成」：どの候補から作っても、編集画面に **同じ元データと列対応** が残り、データ入りで開く。

## 3. 今のコードとの関係（確認した範囲）

- 表の貼り付けの読み取りは既存（`src/features/editor/dataCheck.ts`：`checkPaste`、`tableFromGrid`。上限 `LIMITS` 行2000・列200）。
- 組み替え後の入れ物は `Dataset`（`src/registry/dataset.ts`）。
- プレビューは `proposalSvg(proposal, locale)`。ここにユーザーのデータを渡せるようにする。
- AI 相談（`/api/ai/consult`）は文章だけを読む。
- 既存レシピ（`src/registry/recipes.ts`）のうち、第1段階の候補に使えるもの（§7）：
  - 項目×1指標：`COMP_RANK`（横棒）、`COMP_COLUMN`（縦棒）
  - 時間：`TREND_LINE`（折れ線）、`TREND_COLUMN`（時系列縦棒）、`TREND_STACKED`（積み上げ）
  - 実績対比較値：`COMP_TWO_DELTA`、`COMP_VARIANCE`、`COMP_RANK_DELTA`、`COMP_RANK_METRIC2`
  - 関係：`REL_SCATTER`、`REL_BUBBLE`（`REL_QUADRANT` も同じ列でよい）
- **基本表・KPI・増減表の単独レシピは無い**（表は `cagr_table`／`growth_table` として、チャートに添える形のみ）。段階0で、既存の表の部品（`kind: 'table'`）を単独で使えるかを確認する。使えなければ、最小の表レシピ（行×列をそのまま並べる、増減を色分けする）を足す。これは **表の部品の再利用または小さな追加であり、新しいチャート描画エンジンではない**。
- ヒートマップ・小さな複数の棒・一覧（評価）は、定義はあるがレイアウトもレシピも無い（第3段階）。

## 4. 列対応モデル（改訂の中心）

### 4.1 考え方

- 「列の役割」だけを持つ。**特定のチャート名を持たない。** AI の返答は、チャートを選ばない。
- 同じ列対応から、コード側が **複数の候補**（折れ線・縦棒・表など）を作る（§7）。
- 役割：項目／時間／系列／グループ／指標／X／Y／サイズ／比較対象（前年・予算・計画など）／使用しない。

### 4.2 型（確定案、`src/features/data/columnRoles.ts` に置く）

```ts
export const COLUMN_ROLES = [
  'item',     // 行の名前（国・商品・顧客など）
  'time',     // 時間（年・四半期・月・日）
  'series',   // 系列（時間や項目を、さらに色で分ける列）
  'group',    // グループ（地域・カテゴリ。並べ替えや色分けに使う）
  'metric',   // 数値の指標（売上・シェアなど）
  'x',        // 散布図・バブルの横軸
  'y',        // 散布図・バブルの縦軸
  'size',     // バブルの大きさ・規模
  'compare',  // 比較対象（前年・予算・計画・目標など）の数値
  'unused',   // 使わない
] as const;
export type ColumnRole = (typeof COLUMN_ROLES)[number];

export const COMPARE_KINDS = ['prior_year', 'prior_period', 'budget', 'plan', 'target', 'other'] as const;
export type CompareKind = (typeof COMPARE_KINDS)[number];

/** 差の表し方。compare 列の値が「水準」か「差（pp・%）」か。 */
export const COMPARE_FORMS = ['level', 'delta_abs', 'delta_pct', 'delta_pp'] as const;
export type CompareForm = (typeof COMPARE_FORMS)[number];

export const TIME_GRAINS = ['year', 'half', 'quarter', 'month', 'week', 'day', 'unknown'] as const;
export type TimeGrain = (typeof TIME_GRAINS)[number];

export type ColumnAssignment = {
  col: number;                 // 0 始まりの列番号
  role: ColumnRole;
  unit?: string;               // コードが判定した単位。AI が上書きしてもコードが検証する
  // role === 'compare' のとき
  compareKind?: CompareKind;
  compareForm?: CompareForm;
  compareOf?: number;          // 比べる相手の metric の列番号（「CY の売上」に対する「LY の売上」など）
  // role === 'time' のとき（横持ち：列見出しが期間のとき timeCols を使う）
  grain?: TimeGrain;
};

export type ColumnRoleMap = {
  version: 1;
  /** 行の向き。'rows' は 1 行が 1 項目（ふつう）。'timeAcrossColumns' は列見出しが期間（横持ち）。 */
  layout: 'rows' | 'timeAcrossColumns';
  assignments: ColumnAssignment[];
  /** 横持ちのとき、期間にあたる列（時間の役割を、列の集合で表す） */
  timeCols?: number[];
  /** 迷った点（ユーザーに見せる。数値は含めない） */
  notes?: string[];
  source: 'ai' | 'rules' | 'user';   // 誰が決めたか（画面に出す）
};
```

### 4.3 検証の規則（`validateRoleMap(profile, map)`、zod＋追加検査）

- 列番号は範囲内・重複なし。未指定の列は `unused` とみなす。
- `item` は 0 または 1 列。`time` は 0 または 1 列（`timeAcrossColumns` のときは `timeCols` が 2 列以上で、`time` の割り当ては無い）。
- `metric` は 1 列以上、かつ **コードが数値と判定した列だけ**（文字列の列を metric にできない）。`x`／`y`／`size`／`compare` も数値列のみ。
- `compare` は `compareOf` が metric 列を指す。`compareOf` が無い場合は、同じ単位の最も近い metric に自動で結ぶ（結べなければ `notes` に残して `unused` に戻す）。
- `x` と `y` は同時に 1 列ずつ。`size` は `x`・`y` があるときのみ。
- `series` は `time` または `item` と同時に指定できるが、`group` と同じ列にはできない。
- 違反した割り当ては **捨てて**、残りで続行するか、成立しなければ規則による推定（§6）に戻す。

### 4.4 列の特徴（コードが計算する。AI へ送るのはこれだけ）

```ts
export type ColumnProfile = {
  col: number;
  header: string;                         // 見出し（60 文字で切る。数値のみの見出しは「列N」に置き換え）
  kind: 'number' | 'percent' | 'currency' | 'date' | 'text';
  unit?: string;                          // 例：'%'、'€'、'pp'
  hasMissing: boolean;                    // 欠損があるか（個数ではなく有無）
  distinctClass: 'unique' | 'few' | 'many'; // 値の種類の多さ（具体的な値は持たない）
  isTimeLike: boolean;                    // 期間として読めるか（年・四半期・月など）
  grain?: TimeGrain;
  isMonotonic?: boolean;                  // 時間として昇順か
};

export type TableProfile = {
  rowCount: number;
  colCount: number;
  headerLooksTimeAcrossColumns: boolean;  // 列見出しが期間として並んでいるか（横持ち）
  columns: ColumnProfile[];
};
```

`TableProfile` は **セルの値を一切持たない**（見出しと、コードが計算した特徴のみ）。

### 4.5 列対応から作る「形」

役割の組み合わせから、コードが形を決める（AI は形を決めない）：

| 形（`DraftShape`） | 条件 | 例 |
|---|---|---|
| `item_metric` | item＋metric 1 | 国別売上 |
| `time_metric` | time（または横持ち）＋metric 1 以上 | 月別売上 |
| `item_compare` | item＋metric＋compare、または metric 2 つ | 商品別の実績と予算 |
| `relation` | item＋x＋y（＋size） | ASP 前年比×シェア前年差×配荷 |
| `exact_table` | 上のどれでも成立するが、数値を正確に見たい／形が複数ある | 一覧、KPI、増減表 |

1 つの列対応が複数の形に当てはまることがある（例：時間＋metric は `time_metric` と `exact_table`）。形ごとの候補は §7 で並べる。

## 5. AI へ送るデータ（第1段階）

- 送る：質問の文章、`TableProfile`（列見出し・型・単位・行数・列数・欠損の有無・期間列の有無）。
- **送らない：** セルの値、項目名（国名・商品名・会社名・顧客名）、表の先頭 5 行（旧案を取りやめ）。
- 見出し行の誤判定への対策：コードは見出しとして読んだ行が本当に見出しか（全部が数値のセルでないか、文章として読めるか）を確かめる。数値だけのセルは「列N」に置き換える。確信が持てないときは AI を呼ばず、ユーザーに見出し行を選んでもらう。
- 質問の文章はユーザーが書いたもの。文章の中に数字があっても、そのまま送る（ユーザーの入力）。
- 返ってくるもの：`ColumnRoleMap`（§4.2）のみ。数字・文章は返させない。
- 列対応を判断できないとき（AI が確信を持てない、検証で破棄された）は、**推測せず**、画面でユーザーに選んでもらう（§6）。
- 表示の文言（統一）：「AIには相談文と、表の列見出し・形式を送ります。セルの値は送りません。」を次の 3 か所に同じ文で出す：トップページ、データの取り扱いページ、AI 相談画面（「AI 相談」ボタンの近く）。ja／en の両方、文言は i18n の 1 つのキーを共有して食い違いを防ぐ。
- テスト：セルの値が AI への送信内容に出ないことを、**固有の目印の値**を入れた表で確かめる（§9 T-PRIV）。

## 6. 列対応の決め方（3段のフォールバック）

1. AI の返答を検証して採用する（`source: 'ai'`）。
2. AI が失敗した・検証で全部が破棄された・オフラインのとき：**規則による推定**（`inferRoles(profile)`）。例：日付列→time、唯一の文字列ユニーク列→item、「前年／LY／Budget／Plan／予算／計画」を含む見出し→compare 候補、1 つだけ数値列→metric、数値 2 列で「X／Y」の語→x／y。確信が低い場合は役割を決めず、次へ。
3. 手動指定：画面で各列の役割を選ぶ（`source: 'user'`）。ユーザーの指定は常に優先し、AI の再実行で上書きしない。

役割が変わると、全候補をコードだけで描き直す。AI は呼ばない。

## 7. 候補の生成と並び順

### 7.1 方針

- 候補は **業務での使用頻度と質問への適合度** で並べる。「珍しさ」では並べない。
- Mekko やバブルを常に目立たせる優先は設けない。質問の適合度が高い場合だけ入れ替える（質問に「規模と構成」→Mekko、「関係」→バブルなど。既存の目的→レシピの推薦を使う）。
- 候補を作る関数 `candidatesFor(shape, roleMap, profile)` は、レシピ ID の並びを返す。**レシピが必要とする `Dataset` への組み替えは `reshape(table, roleMap, recipe)`**（純粋関数）。

### 7.2 形ごとの並び（既定）

| 形 | 並び（左が先頭） | 使うレシピ |
|---|---|---|
| 項目比較（`item_metric`） | 横棒 → 縦棒 → 表 | `COMP_RANK` → `COMP_COLUMN` → 基本表 |
| 時系列（`time_metric`） | 折れ線 → 時系列縦棒 → 表（series があれば積み上げ縦棒を折れ線の次に） | `TREND_LINE` → `TREND_COLUMN`（→`TREND_STACKED`）→ 基本表 |
| 実績対予算・前年比（`item_compare`） | 差分バー／集合棒 → 増減付き表 | `COMP_VARIANCE`／`COMP_TWO_DELTA` → 増減表 |
| 構成 | 積み上げ → 100%積み上げ → Mekko | `TREND_STACKED`／`MIX_SNAPSHOT` → `MIX_BAR100` → `MIX_MEKKO` |
| 要因 | ウォーターフォール → 要因バー | `CONTRIB_WATERFALL` → `CONTRIB_DRIVERS` |
| 関係（`relation`） | 散布図 → バブル | `REL_SCATTER` → `REL_BUBBLE` |
| 多指標評価 | ヒートマップ表 → 小さな棒の並び | 第2段階：既存の表を再利用できる範囲で／本格版は第3段階 |

「構成」「要因」は、データの形が成り立つときだけ候補に出す（旧案どおり、足りない情報は理由つきで案内する）。

### 7.3 マトリックスの扱い（指示 5）

- 本格的な評価マトリックス（ヒートマップ・一覧のレイアウトとレシピ）は **第3段階のまま**。
- 既存の「基本表」「ヒートマップ型の表」を再利用できる場合は、**第2段階で表形式の候補として接続してよい**。
- 新しいチャート描画エンジンは、第1段階に前倒ししない。

## 8. 回数と料金プラン（確定）

- 表を含む場合も、従来の **「AI 相談 1 回」** として数える（別枠にしない）。
- 数えないもの：候補の切り替え、列の使い方の修正、再描画、スライドの作成。
- **無料プランでも使える**（実データで候補が描かれる体験を入口にする）。無料の累計 5 回の中で数える。
- AI が失敗した場合（規則による推定や手動指定に戻った場合）は、既存の失敗時の扱いに合わせて回数を戻す（既存の AI 相談のルールを確認して合わせる。段階 0 で確認）。

## 9. 型とテストケース（実装前に確定）

テストは vitest、`src/features/data/*.test.ts`。固定の入力は `src/features/data/fixtures/`（7 か国の表、月別売上、実績・予算、X／Y／規模、横持ち）。

### T-ROLE（列対応モデルの検証：`validateRoleMap`）
1. 正常：item＋metric 1 → 通る。
2. item が 2 列 → 後の割り当てを捨て、警告が `notes` に出る。
3. 文字列の列を metric にする → 捨てる。
4. 範囲外の列番号・重複 → 捨てる。
5. `compare` に `compareOf` が無く、同じ単位の metric が 1 つ → 自動で結ぶ。結べない → `unused`。
6. `x` だけで `y` が無い → x を捨てる。`size` が `x`／`y` 無しで指定 → 捨てる。
7. 時間列と `timeAcrossColumns` を同時に指定 → 後者を優先して時間列の割り当てを捨てる。
8. 全部が捨てられた → 空の対応ではなく「判断不能」を返す（§6 の次の段へ）。

### T-PROFILE（列の特徴：`profileTable`）
1. 7 か国の表：型（percent／currency／text）と単位（%、€、pp）を判定。
2. 年・四半期・月の見出しを持つ横持ち → `headerLooksTimeAcrossColumns`、`grain` を判定。
3. 欧州表記（`1.234,5`）、%、合計行、エラー値 → 既存の `dataCheck` と同じ結果。
4. 数値だけの見出しは「列N」に置き換わる。60 文字を超える見出しは切る。
5. 行数・列数が上限（2000／200）を超える → 拒否（既存どおり）。
6. **`TableProfile` のどこにもセルの値が含まれない**（型で持たない＋下の T-PRIV で確かめる）。

### T-PRIV（AI へ送る内容：`buildConsultPayload`）
1. 目印の値を持つ表を作る：項目名「ZZ_SECRET_ACME」、数値 `8675309.123`、`4242424242`（各セル）。
2. `JSON.stringify` した送信内容に、これらの文字列が **1 つも含まれない**。先頭 5 行も含まれない。
3. 送信内容に含まれるのは、質問の文章、見出し、型、単位、行数・列数、欠損の有無、期間列の有無のみ（許可リストの項目だけ。他のキーがあれば失敗）。
4. 見出しが数値だけのとき（見出し行の誤判定）は、値が見出しとして送られない（「列N」）。
5. `/api/ai/consult` のリクエスト本文を検査する結合テスト：表の値を含むフィールドが無い。

### T-INFER（規則による推定：`inferRoles`）
1. 日付列＋数値 1 列 → time＋metric。
2. 文字列のユニーク列＋数値 1 列 → item＋metric。
3. 「CY」「LY」の見出し → metric＋compare（prior_year）。「Budget」「Plan」「予算」「計画」 → compare。
4. 見出しに「vs LY (pp)」のような差の表現 → `compareForm: 'delta_pp'`（水準でない）。
5. 確信が低い（候補が複数）→ 役割を決めず「手動指定が必要」を返す。推測で埋めない。

### T-SHAPE／T-CAND（形と候補）
1. 国別売上 1 列 → `item_metric`、候補は `COMP_RANK` が先頭、次に `COMP_COLUMN`、表。
2. 月別売上 → `time_metric`、`TREND_LINE` が先頭、次に `TREND_COLUMN`、表。series があれば積み上げが `TREND_COLUMN` の前に出る。
3. 商品別の実績・予算 → `item_compare`、差分バー／集合棒が先頭、増減付き表が次。
4. X・Y・規模の列 → `relation`、`REL_SCATTER` が先頭、`REL_BUBBLE` が次（size があれば両方出る）。
5. 質問が「関係と規模」→ バブルが先頭に入れ替わる。質問が無関係なら入れ替わらない。
6. Mekko・バブルは、条件（規模の列がある／size がある）を満たさない限り出ない。出ない理由を返す。
7. 同じ入力は同じ順（決定的）。

### T-RESHAPE（組み替え：`reshape`）
1. 数値は元のセルから 1 桁も変えずに写る（丸めは表示のみ）。
2. 算出値（差・割合）は印つき。AI の出力に数値が含まれる場合は破棄。
3. どの候補（折れ線・縦棒・表）から作っても、`Dataset` の元データ（`long`／生の表）と `ColumnRoleMap` が **同じ**で残る。
4. 欠損・0・負値・外れ値でも落ちない。
5. 行数が上限を超えるとき、切り捨てずに指摘して拒否する。

### T-FLOW（流れ）
1. 候補を切り替えても `consultWithAi` が呼ばれない（モックで呼び出し回数 = 1）。
2. 列の使い方を直しても AI を呼ばない。
3. AI が失敗（例外・不正な返答）しても、規則による推定、または手動指定の画面に戻れる。
4. 回数は 1 回の相談で 1 だけ増える。切り替え・修正・再描画・スライド作成では増えない。無料プランでも実行できる。
5. 表を含まない相談は、今までどおり動く（回帰）。

### T-I18N

## 11. 安全と品質

- 数字は元の表から写すだけ。AI の出力に数字は含めない。
- 事実の範囲：見出し・説明は「A が下がり、B が上がった」まで。「A が B の原因」は書かない（文章はテンプレート。AI は使わない）。
- 作る前の指摘：同じ値の並び（貼り間違いの疑い）、単位の混在、外れ値、必要な列が無い（規模が無く Mekko は作れない、など）。
- 失敗時：AI が呼べない・対応表が不正なときは、規則の推定→手動指定の順で戻る（§6）。
