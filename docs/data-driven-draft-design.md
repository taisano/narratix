# 設計メモ：データと質問から、実データで描いた下書きを出す

2026-10-19、Claude。実装の前の設計案（コードは変えていない）。調査は `docs/data-to-slides-feasibility.md`。

## 1. ゴール

ユーザーが「質問の文章」と「Excel の表」を入れて「AI 相談」を押すと、次の画面のチャート候補が、**見本データではなくユーザーのデータで描かれて**見える。候補を選んで「スライドを作成」を押すと、編集画面が**データが入った状態**で開く。チャートの種類はユーザーが選ぶ（AI は候補を出すだけで、絞らない）。

## 2. ユーザーの流れ

1. 入力：「AI 相談」の入力欄に、質問の文章と、表の貼り付け（任意）。表が無ければ今までどおり。
2. 「AI 相談」を押す：表を読み、AI が「どの列を何に使うか」の対応表を作る（AI の呼び出しはここで1回）。
3. おすすめの画面（`RecipeScreen`）：候補のプレビューが、ユーザーのデータで描かれる。各候補に「列の使い方」の1行が付き、直せる。
4. 候補を選ぶ：別のチャート（例：バブルでなくマトリックス）にも、その場で切り替えられる。切り替えても AI は呼ばない。
5. 「スライドを作成」：編集画面が、組み替え済みのデータ入りで開く。元の貼り付けた表（`long` の仕組み）は残り、あとから列の使い方を変えて組み替え直せる。

## 3. 今のコードとの関係（確認した範囲）

- 表の貼り付けの読み取りは、すでにある（`src/features/editor/dataCheck.ts`：`checkPaste`、`tableFromGrid`。単位・%・欧州表記・合計行・エラー値の扱い、行数・列数の上限 `LIMITS` を含む）。
- 組み替え後のデータの入れ物は `Dataset`（`src/registry/dataset.ts`）。`rows`、`cols`、`periods.current/base`、列ごとの方向と単位（`colMeta`）、行のグループ（`groups`）、縦長の元の表と切り出し方（`long`、`melted`）を持つ。
- プレビューは `proposalSvg(proposal, locale)` が、見本データから実際のエンジンで描いている。ここに「ユーザーのデータ」を渡せるようにする。
- AI 相談（`/api/ai/consult`）は文章だけを読む。表の見出しや行は読んでいない。
- 注意：ヒートマップ・小さな複数の棒・一覧（評価）は、`registry/charts.ts` に定義があるが、描画のレイアウトが `src/engine/layout/charts/` に見当たらず、レシピもない。マトリックスを選べるようにするには、レイアウトとレシピの追加が要る（第3段階）。

## 4. AI とコードの分担

| 仕事 | 担当 | 理由 |
|---|---|---|
| 表を行・列に分け、型（項目・数値・文字・期間）と単位を判定する | コード | 決まった規則。誤りを防ぐ |
| 列を「何に使うか」を決める（項目、X、Y、サイズ、左の指標、右の指標、系列、グループ） | AI | 質問の意味と列名の理解が要る |
| 候補のチャートを選ぶ | 既存の推薦（目的→レシピ） | すでにある。AI が決めない |
| 表の数字をチャートの形に写す | コード | 数字を間違えない・捏造しない |
| 差・割合・逆算（LY など）の計算 | コード。算出値には印 | AI に計算させない |
| 文章（見出し・説明）を作る | 事実の範囲のテンプレート。AI は使わない（第1段階） | 因果の言い切りを防ぐ |

## 5. データの受け渡し

AI へ送るもの（最小限）：質問の文章、列の見出し、列ごとの型と単位、先頭の数行（最大5行）、行数。**表の全体は送らない。** 数字の全部が外部の AI に渡らないようにし、費用も抑える。送る内容は、プライバシーのページに「AI 相談に表の見出しと数行を送る」と追記する。

AI が返すもの（列の対応表、`ColumnRoleMap`）：

```ts
{
  rowLabel: number;                       // 行の名前の列（例：Country）
  roles: { col: number; role: 'x' | 'y' | 'size' | 'left' | 'right' | 'series' | 'group' | 'value' | 'skip'; unit?: string }[];
  notes?: string;                         // 迷った点（ユーザーに見せる）
}
```

コードは、この対応表を zod で検証する（範囲外の列、重複、役割の矛盾は破棄して、規則のみの案に戻す）。

組み替え（`reshape`、新規。`src/features/data/`）：`(表, ColumnRoleMap, レシピ) → Dataset`。レシピのデータの形ごとに1つ（BUBBLE、項目×1指標、項目×2指標、…）。純粋関数で、単体テストを付ける。逆算などの算出値は、`Dataset` ではなく「算出の印」のリストに残し、画面で見せる。

## 6. 画面の変更

- 入力画面：表の貼り付け欄（既存の貼り付けの部品を再利用）。貼った表のチェック結果（`DataCheckPanel`）をその場で出す。
- おすすめの画面：候補のプレビューをユーザーのデータで描く。「列の使い方」の行（例：X＝ASP の前年比、Y＝シェアの前年差、サイズ＝加重配荷）と「直す」。直すと、全候補が描き直される（コードのみ）。
- 算出値の確認：「LY は CY−差分で算出しました」のような印と、確認のチェック。確認するまで算出値を使う案は出さない。
- 編集画面：データ入りで開く。上限・単位・グループの設定は、既存のまま。

## 7. 安全と品質

- 数字は元の表から写すだけ。AI の出力に数字は含めない。
- 事実の範囲：見出し・説明は「A が下がり、B が上がった」まで。「A が B の原因」は書かない。
- 作る前の指摘：同じ値の並び（貼り間違いの疑い）、単位の混在、外れ値（軸の扱いを選べる）、必要な列が無い（規模が無く Mekko は作れない、など）。
- 失敗時：AI が呼べない・対応表が不正な時は、規則のみで列を推定するか、今までの流れ（自分で貼る）に戻す。

## 8. 回数と料金プランへの影響（決めること）

- 「AI 相談（1枚）」の1回として数える案（簡単）と、データ読み取りを別枠にする案。推奨は、まず1回として数える。
- 候補の切り替え・列の使い方の修正は、AI を呼ばないので数えない。
- 無料プラン（累計5回）の人にも、この機能を使わせるか。使わせるなら「試して価値を感じてもらう」役目になる。

## 9. 段階と完了条件

| 段階 | 内容 | 完了条件 |
|---|---|---|
| 0 | 準備：`ColumnRoleMap` の型と zod、`reshape` の土台、`proposalSvg` にデータを渡せるようにする | 型・単体テストが通る。画面の変化なし |
| 1 | 第1段階の形：項目×1指標、BUBBLE・散布図、項目×2指標。AI 相談に表を送り、プレビューとスライド作成をデータ入りに | ご提示の7か国の表で、国別の棒と、バブルが実データで出て、編集画面にデータが入る |
| 2 | 列の使い方の確認・修正の画面、算出値の印と確認、作る前の指摘 | 列を直すと全候補が描き直される。貼り間違いの疑いを指摘できる |
| 3 | マトリックス（評価）：レイアウトとレシピの追加。LY の逆算つきの2時点の形 | マトリックスを候補に出して選べる |
| 4 | 複数枚（Story）への接続、プライバシーのページ・料金の表示の更新 | Pro の複数枚で、データ入りの下書きが出る |

各段階は、typecheck・テスト・build を通してコミットし、段階ごとにユーザーの確認を取る。

## 10. 決めてほしいこと

1. 第1段階の範囲（項目×1指標、BUBBLE・散布図、項目×2指標）でよいか。
2. AI へ送る内容（見出し・型・先頭5行）でよいか。外部の AI にデータの一部が渡る点を、利用者にどう伝えるか。
3. 回数の数え方（§8）。
4. 無料プランの人にも使わせるか。
5. マトリックスの優先度（第3段階のまま、または第1段階に前倒し）。
