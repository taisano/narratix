## 2026-09-23（レジストリ）

- **設定の適用先は Control 側だけに持つ**：チャート定義に `controls` 一覧は置かず、`controlsFor(chart)` で逆引きする（二重管理を避ける）。補完パーツは、チャート側に「推奨」、補完パーツ側に「適用可能（appliesTo）」を持ち、推奨 ⊆ 適用可能をテストで保証する。appliesTo は設計書の「主な適用チャート」と各チャートの「推奨補完」の和集合。
- **見せられる／見せられないは語彙（AspectId）で持つ**：設計書の日本語の説明を20語の語彙に置き換え、補完パーツの `covers` と突き合わせる。語彙は `src/registry/aspects.ts`。
- **スキーマの互換**：MATRIX 系チャート（trend / comparison）は MEKKO データも受け取れる（どちらも「行×列の実数」）。p05 の左の合計棒（stacked_100）を MEKKO データから描くため。transform を持つパネルはスキーマ照合を省き、変換後の形は配置エンジン側で確かめる。
- **パネル型の補完パーツの置き場所**：揃えた表は既定で p02（上下 3:1）の下、Mekko は p05 の右下、横棒ランキングとヒートマップは p03 の右（行揃え）。示唆ボックスは p03 の右（3:1）。
- **ViewSpec の id / version は任意**：AI が返す JSON には含まれないため。保存時に DB 側で付ける。
- **sparkline は保留**：3時点以上が必要だが、Dataset は current / base の2時点しか持てない。Dataset の拡張と合わせて決める。
- **slope は比較期間を必須にしない**：MATRIX_TIME_SERIES の2行（2時点）でも描けるため。

## 2026-09-23（transform と配置エンジン）

- **見本をゴールデン値にする**：`scripts/extract-reference-golden.mjs` が `reference/mekko-builder.html` の `model()` と `layout()` を Node でそのまま実行し、5パターン（標準、期間の伸び率、強調、表なし、入力順）の結果を `src/engine/__fixtures__/reference-mekko.json` に書き出す。エンジンはこれと全アイテムの座標・文言・色が一致することをテストで保証する。見本を変えたらスクリプトを再実行する。
- **見本の構成は「p02 上下（上：Mekko、下：揃えた表）」で再現する**：揃えの指定でつながったパネルの間隔は 0.14 in（通常は 0.25 in）。列で揃える表は、比率で決まる高さより内容が小さければ内容の高さに縮め、余りをチャート側に渡す（比率は上限として働く）。
- **スライド枠の寸法を見本に合わせた**：タイトル y=0.32、パネル領域 1.18〜6.90、出典 y=7.02（`SLIDE_FRAME`）。
- **Dataset に `dimensions`（行・列が何を表すか）を追加**：Mekko の注記「高さ：形状の構成比」に必要なため。未入力なら「セグメント」。
- **Mekko の左余白**：揃えた表がある、または左に y_scale で揃えるパネルがない場合は 1.75 in（見本と同じ）。左に合計棒がある p05 で表もない場合は 0.6 in。
- **描画を実装済みのチャートは mekko と stacked_100 のみ**（`IMPLEMENTED_CHARTS`）。他は `ComposeError('not_implemented')` を返す。

## 2026-09-23（プレビュー画面）

- **画面の多言語は自前の小さな仕組みにした**（`src/i18n/ui.tsx` の `useT()`）。next-intl は URL に言語を入れるルーティングが前提で、今の1画面構成には重いため外した。翻訳ファイル（messages/ja.json・en.json）の形は同じなので、必要になれば置き換えられる。日英のキーと差し込みが揃っていることはテストで確認する。
- **空きスロットは詰める**：パネルを置かないスロットは幅0・間隔0にする。Mekko ビルダーは常に p05 を使い、左の合計棒・下の表のオンオフは「そのスロットを空ける」で表す。
- **p05 で左に合計棒があるとき**、Mekko の左余白は下の表の行ラベルが入る幅まで詰め、「形状構成比（2025年）」の見出しは出さない（合計棒の見出しと重複するため）。

- **画面の状態 → ViewSpec**：画面は `BuilderState` を編集し、描画のたびに `toViewSpec()` で ViewSpec に変換してレジストリで検証してから描く。レイアウトと置き場所は補完パーツ aligned_table の定義から取る。

- **PPTX は Scene をそのまま置く**（`src/export/pptx/scene-to-pptx.ts`）。チャート固有のルールは持たない。図形・文字の位置と大きさが Scene と ±1 EMU で一致すること、揃えた表の列幅が Mekko の列と一致することを、生成した PPTX の XML を展開してテストする。
- **フォントはスライドの言語で決める**：日本語 Meiryo、英語 Arial（`SLIDE_FONTS`）。社内規定のフォントに変える設定は後から。

- **元データのスライド**（付録）も Scene として配置する（`layoutDataSlide`）。行が多い場合のページ分けは未対応。
- **表の行ラベル列の余白を 0.4in に**：0.2in では PowerPoint／代替フォントで「市場全体 CAGR」が折り返した（LibreOffice で PPTX を画像にして確認）。
- **強調時の凡例は色のまま**（見本と同じ）。強調していない系列の凡例をグレーにするかは要検討。

## 2026-09-23（ログインと保存）

- **テーブル**：projects / datasets / view_specs / view_spec_versions。すべて owner_id = auth.uid() の RLS。anon には権限を与えない。履歴（versions）は追記のみ。
- **保存は RPC `save_chart` 1回**：データ・ViewSpec・履歴をまとめて書き、version を進める（security invoker なので RLS がそのまま効く）。新規保存で最初のプロジェクト「マイプロジェクト」を自動で作る（プロジェクトの画面はまだない）。
- **ViewSpec と画面の状態を両方保存する**：`spec` はレジストリで検証済みの ViewSpec（出力・AI の正本）、`ui` は開き直すための BuilderState。検証に通らない状態は保存しない。
- **削除は datasets を消す**：外部キーの cascade で ViewSpec と履歴も消える。
- **ログインはメールのリンク（PKCE）**：リンクから戻るとブラウザのクライアントが ?code= を自動で交換する。サーバー側で Supabase を使う処理はまだないので、proxy.ts（旧 middleware）とコールバック用のルートは置いていない。サーバー側で読む処理を足す時に入れる。
- **テスト**：migration は PGlite に Supabase の auth を模したスキーマを作って実行し、保存・版の進み・他人の行が見えない／書けない・未ログインで読めない・履歴を書き換えられない、を確かめる。画面の流れは Playwright で Supabase を差し替えて確認した（自動テストには入れていない）。

## 2026-09-24（依存関係の注意）

- **npm audit の high 2件は pptxgenjs → image-size**：画像を読み込む時の不具合（DoS）。このアプリは PPT に画像を入れないので該当しない。`npm audit fix --force` は pptxgenjs を 2.2 に戻して出力が壊れるため実行しない。画像を入れる機能を足す時に、pptxgenjs の更新と合わせて見直す。

## 2026-09-24（マイページとチャート名）

- **チャート名（name）をスライドのタイトル（title）と分けた**：一覧で見分けるための名前。初回保存と「別名で保存」で名前を聞く（初期値はスライドのタイトル／「○○ のコピー」）。上書き保存では聞かない。名前の変更は版を進めない。
- **migration は追記で足す**（`20260924000000_chart_name.sql`）。save_chart の引数が変わるため、関数を作り直している。Supabase 側で SQL を実行するまで、新しい画面からの保存は失敗する。
- **マイページ（/charts）**：縮小プレビュー（保存した画面の状態から、その場で配置・SVG を作る）、検索（名前・タイトル）、並び替え（更新・作成・名前）、開く・名前変更・複製・2段階の削除。一覧は1回の取得で全件（件数が増えたらページ分けを入れる）。
- **エディタとマイページの行き来は URL で渡す**（`/?chart=<id>`、`/?new=1`）。エディタに未保存の変更があれば、進む前に確認を出す（ブラウザの確認ダイアログは使わない）。
- **ヘッダー・ログイン・画面の言語は AppShell にまとめ**、layout.tsx で全画面に置く。共通のスタイルは `src/features/ui.module.css`。

## 2026-09-24（Trend・Comparison と行と列の入れ替え）

- **NarratiX のルールに合わせた点**（`docs/narratix-rules.md`）：比較は「行＝対象（多くは年）、列＝並べる項目」。対象の既定は最後の行、並び順は降順・昇順・入力順、空欄の列は除く。折れ線は空欄で途切れる。強調は対象を濃紺・他をグレー、強調した線を最前面に。CAGR は横軸が年のとき最初→最後の年。数値表記は formatDriverMetricValue_ の規則。既定値（目盛線・値ラベル OFF、マーカー ON）。
- **NarratiX から変えた点**：値の軸は 0 ちょうどから（下に余白を付けない）、マイナスの棒は 0 の線から下（左）へ、目盛はきりの良い刻み（1・2・2.5・5×10^n、区間 3〜7、端が値に最も近いもの）、数値に桁区切り。数値表記の既定は「そのまま」（NarratiX の自動 K/M は選択肢に残す）。
- **行と列の入れ替え（axis_swap）はデータを変えない**：描く直前に transpose を掛ける。Contribution 以外の全チャートで使える（NarratiX では Mekko・Evaluate は固定だった）。同じスライドの揃えたパネル（Mekko の左の合計棒・下の表）にも同じく掛ける。表示する行・列の絞り込みは入れ替えの前（入力した表の行・列）に対して行う。
- **設定の候補は入れ替え後の軸から**：強調＝列（系列）、比較の対象・基準・比較先＝行。レジストリの `dataSource` で持つ。候補にない値は ViewSpec に入れない（既定に戻る）。
- **配色**：推移・比較の系列は NarratiX の PROFESSIONAL_DISTINCT_PALETTE、構成系（Mekko・積み上げ・100% 積み上げ）は Mekko の見本の配色。
- **CAGR 注記は比較期間を使わない**（NarratiX と同じく横軸の年から計算）。レジストリの requiresBase を never に変えた。
- **保存形式 v2**：チャートの種類・設定・補完パーツを汎用に持つ。v1（Mekko 専用）は読み込み時に自動で変換し、次に保存した時に v2 で書き直される。
- **エディタのフォルダ名を editor に変更**（mekko-builder から）。ブラウザ保存のキーは互換のため据え置き。

## 2026-09-24 3つの入り口で「レシピ」を共通の単位にする
- 相談（AI）・目的・チャートのどの入り口でも、②で選ぶものは「レシピ」（メインのチャート＋付け合わせの表・補完パーツ＋説明）にそろえる。チャート1つだけのレシピもある。
- 入り口ごとに違うのは絞り込み方だけ：相談＝AI が最大3つ選ぶ（1回だけ）、目的＝その目的のレシピ、チャート＝そのチャートがメインのレシピ（＋別の目的の先頭レシピを提案）。目的・チャートからは AI を使わない。
- 並びは「先頭＝リード案、次の2つ＝サブ案、残り＝ほかの候補（折りたたみ）」。保存は選んだレシピの ID。
- 理由：組み合わせ（チャート＋表）をどの入り口からも出せる、説明文を1回書けば済む、②の画面が1種類で済む。詳しくは `docs/consultation-flow.md`。
- ②の絵はデータ入力前なので、名前・数値を入れない抽象図にする。

## 2026-09-24 推薦レシピの土台（src/registry/recipes.ts）
- **レシピはコードの中に置く**（Supabase ではなく）。チャート・補完パーツ・レイアウトと同じレジストリの一部なので、「存在しないチャートや設定を指すレシピ」はテストで弾ける。版は `RECIPE_DB_VERSION`（ViewSpec の `recipe.version` に残る）。
- **17レシピ**：推移8・比較5・構成4。推移・比較・構成のすべてのチャートに、チャート1つだけのレシピがある。ID は指示書に合わせて大文字（`TREND_CAGR_TABLE` など）。
- **見せられる／見えにくいは手で書かない**：チャートの shows / cannotShow、補完パーツと表の covers から組み立てる（`recipeAspects`）。レシピだけの注意は `extraCannotShow`。
- **見えにくいことへの案内**（`recipeRemedies`）：先にメインのチャートに足せる補完パーツ、無ければそれを見せられる別のレシピ（目的が重なるもの優先）。
- **相談からの並べ方は規則で決める**（`rankRecipes`・`RECIPE_SCORING`）：主な目的 +40／副の目的 +25／違う目的 −40、年が要るレシピは期間が書かれていれば +20（無ければ −20）、場面 +10、成長率・規模・正確な値が必要で見せられれば各 +10、読み取りが重い −10。違う切り口を並べるため、同じメインのチャートは1つまで、主な目的が重なると −15。40点未満は出さない（無理に3案目を作らない）。指示書の例（海外5地域・経営会議）で、指示書と同じ3案・同じ順になることをテストで固定。
- **AI の入出力の形**（`consultation.ts`）：分類（不明は null / 'unknown'）と recipe_id・reason_codes だけ。JSON Schema は `consultationJsonSchema()`。保存する推薦の状態は `ai_used_after_data_input: false` を型で固定。
- **データを入れた後の確認はエンジン側**（`checkRecipeData`・`recipeIssueText`）：データの形、数値の有無、行数、年（1900〜2100 が2つ以上）、開始年・終了年の欠け（指示書の定型文）、CAGR の N/A、比較期間、系列の多さ。AI は使わない。
- **Mekko のレシピは Mekko の形のデータが必要**（今の互換表どおり）。Mekko の形のデータなら推移・比較のレシピも描ける。
- **描けるかどうかは別に判定**（`recipeRenderable`）。今描けるのは9レシピ。CAGR 表（`cagr_table`）、集合縦棒、100%横棒、差分バー、スロープはこれから作る部品。
- 足したもの：表 `cagr_table`、変換 `endpoints`（最初と最後の時点だけ。年なら最小と最大の年）、CAGR 注記を集合縦棒にも使えるように。

## 2026-09-24 エディタを「画面の高さに収める作業台」にする
- サイドバーを下までスクロールすると、スライドとデータが見えなくなっていた。ページ全体ではなく、サイドバー・スライド・データを別々にスクロールさせる。
- 右側はスライドとデータを上下に分け、境目をドラッグ（矢印キー、ダブルクリックで半々）か「スライドを大きく／半々／データを大きく」で大きさを変える。スライドは欄の中に 16:9 のまま収める（container query）。大きさはこのブラウザに覚える。
- サイドバーの欄は見出しで開け閉めでき（`<details>`）、開閉もこのブラウザに覚える。「表示する行・列」は最初は閉じておく。
- 幅 1000px 以下はページ全体をスクロールし、右側を上に固定して「スライド／データ」のタブで切り替える。
- ③（データと詳細設定）の画面も同じ考え方で作る。

## 2026-09-24 補完パーツを「注記・添え・別の1枚」の3段で整理する
- 一覧（合意済み）：Claude Docs「添えパーツの一覧（Chart Advisor）」 https://claude.ai/code/artifact/7b4b81c0-f4f2-4558-add8-2766bf350ded
- 注記（チャートの中、1点）と添え（軸を揃えて横か下に並べる、2点）。添えは共通の9部品（A CAGRの棒、B CAGRの表、C 最新の構成比、D 構成比の変化、E 揃えた表、F 前年比、G 全体の構成、H 合計の推移、I 示唆ボックス）で、揃える軸は「項目・系列・全体」。
- ③のメニューは部品名ではなく「何を言えるようになるか」でまとめ、そのチャートに合う物はすべて選べる。使えない物はグレーで理由を添える。おすすめは印だけ。

## 2026-09-24 新しい画面の流れ（① 入り口・② 切り口を選ぶ）を /start に作る

## 2026-09-24 プロジェクト＝データ1つ＋スライド N 枚（保存形式 v3）
- 1つのデータから複数の見せ方を作るのが売りなので、エディタの単位を「1枚」から「プロジェクト」に変えた（`src/features/editor/project.ts`）。
- **全スライド共通**：データ・出典・スライドの言語。**スライドごと**：チャート・見出し・設定・補完パーツ・どのレシピから作ったか。

## 値ラベルの出し方と横軸の項目名

- 値ラベル（data_labels）は なし／すべて／最初と最後／強調だけ から選ぶ。折れ線・縦棒・積み上げ・集合縦棒で同じ規則（showLabel）。「強調だけ」で強調が無い時は設定欄にヒントを出す。
- 横軸の項目名（x_labels）は 自動／小さく／縦書き／間引く。自動は2行に入らなければ 8pt。縦書きは -90° 回転（SVG・PPT とも）で、項目名の高さぶんプロットを縮める。間引くは1行に入る間隔で出し、最後の項目は必ず出す（すぐ手前は重ならないよう出さない）。
- 折り返しは空白の切れ目を優先（「2021 Q1」→「2021」「Q1」）。
- 対象：折れ線・縦棒（推移・比較）・積み上げ縦棒・100%積み上げ縦棒・集合縦棒・ウォーターフォール。

## タグと「Library から」

- 保存したチャート（view_specs.tags）と Library の見本（library_items.tags）にタグを付ける。人が付けるタグは任意で10個まで・1つ30字まで。
- スライドの言語のタグ（日本語 / English）は保存・公開のたびに先頭へ自動で付け直す（言語を変えても合う）。画面では外せない「自動」のタグとして出す。
- Library の「カテゴリ」はタグに置き換え（既存のカテゴリは SQL でタグに移す。category 列は互換のため残す）。
- マイページと Library はタグで絞り込める。検索もタグに当たる。
- 見本を公開する時は、相談文・相談の履歴・前の元を外す。複製したプロジェクトには origin（Library の見本）を付け、左側は相談文の代わりに「このチャートの元：Library の見本「〜」から」を出す。古い見本に相談文が残っていても、複製の時に外す。
- タグの列が無い（SQL を流す前）間は、タグなしで読み書きを続ける。

## AI の読み取りを見せる・2つの問い・補足して出し直す・2チャートの切り口

ユーザーの声（2026-09-27）への対応：「規模と成長率」に引っ張られて推移の相談が関係（バブル）と読まれ、AI が相談のどこを重視したかも見えなかった。

- ① AI は focus_phrases（重視した言葉。相談文からそのまま抜き出す）を返す。② の左の相談文に印を付け、提案の見出しの下にも出す。相談文に無い言葉は捨てる。
- ② AI は同じ1回の呼び出しで alternative（見せ方の違うもう1つの問い）も返す。ある時だけ「どちらを中心に見せますか？」を選択式で1つ聞く。
  - 切り替えは規則で並べ直すだけ（AI は使わず、回数も減らない）。
  - もう1つの問いの分類は、元の分類を土台に目的・時間・比較・構成・規模・成長率を差し替えて作る。
- ③ 「提案が意図と違う時は、補足して出し直す」：補足（300字まで）を相談文に付けて AI にもう一度分類させる。AI の相談1回として数える。
  - 相談の履歴には新しく残さない（同じ相談）。
  - AI が使えない時は今の提案をそのまま残す。
- プロンプトの決まりを追加：「規模と成長率」が同じ指標の大きさと伸びで、期間の推移があるなら RELATIONSHIP ではなく TREND。
- ルール版：「牽引」と「停滞・伸び悩み・横ばい」が並ぶ相談は、内訳（BREAKDOWN）ではなく項目どうしの伸びの差（DELTA）。
- ④ 新しいレシピ TREND_LINE_DELTA「成長の軌跡と牽引役を1枚で」（TWO_CHARTS、左右）。
  - 左：折れ線＋右端に CAGR＋最初と最後の値。右：期間の増減額（差分バー）。
  - 推移で比較の意味が DELTA / LEVEL の時に先頭に来る。
  - 強調は左右の両方に効く。レシピの主チャートの既定の設定（値ラベルなど）は、エディターの状態に入れて変えられるようにした。
- 折れ線の値ラベル：同じ年のラベルが近い時は、上の方を上にずらして重ならないようにした。
- 正解表（開発セット）にこの相談を F01 として追加した。
- 注意：share の i18n キー feedback.thanks / send / privacy を、ベータのフィードバック（sitefb.*）が上書きしていたのを元に戻した。

## CAGR 表の列の選択と、AI 相談の残り回数

## 2026-09-27 積み上げの「実数」表示と、新しいチャート「幅が変わる縦棒」

考え方：データの形と問いが同じで、目盛りだけが違うなら「同じチャートの設定」。データの形が変わるなら「新しいチャート」。

- 2期間の積み上げ（share_pair）に設定「棒の高さ：100%／実数」と「棒の中のラベル：%／実数／なし」を足した。

- 新しいチャート「幅が変わる縦棒」（variable_width、目的は関係、データは関係と同じ形）。
  - 幅＝規模（人口・売上など）、高さ＝水準（1人当たり・利益率など）、面積＝全体の量。横軸は幅の累計構成比（0〜100%）。

  - 補完パーツ「参照線」：値と名前を入れられる（空なら幅で重み付けした平均）。名前は棒と重ならない所に置く。
  - 名前が棒の幅に入らない項目は番号にして、下に番号と名前の一覧を出す。
  - 切り口 REL_VARIABLE_WIDTH（関係・比較）。AI 相談では「規模も伝えたい」と読めた時だけ出す（fit.requireSize）。相関だけの相談には出さない。
  - チャート一覧（/start）で Mekko・2期間の積み上げ・ウォーターフォールの次に並べる。
- Mekko の高さは実数にしない：幅と高さの両方に規模が入り、面積が規模の2乗になって大きい項目が実際より大きく見えるため。

## 2026-09-27 スロープの改善と「2指標スロープ」

## 2026-09-27 縦棒＋折れ線（combo、推移）

## 2026-09-28 実データ耐性（第1段）：貼り付けの健康診断

方針（think-cell 出身の知人の助言）：**間違ったチャートを、もっともらしく出さない**。読めない・紛らわしいものは黙って変えず、どのセルが・なぜ・どうするかを Coach の言葉で伝え、利用者が選べるようにする。追う指標は「チャートを作れた割合」ではなく「数値を誤らず、手直しなしで採用できた割合」。

- **セルの読み方**（`dataCheck.ts` の `readCell`。表の中の入力・貼り付けも同じ）：`▲120`・`△5`・`(120)`・`−120` はマイナス、`12%` は 12（% の列）、`1,200`・`1 200`・全角数字・ノーブレークスペース、`¥1.2M`・`1,200千円`・`120億円`（単位は掛けずに記録）。`-`・`N/A`・`未定` は「値なし」、`#DIV/0!` などは Excel のエラー。**どれも 0 にはしない**（空欄にして、診断で伝える）。
- **貼り付けの健康診断**（「Excel・表から貼り付け」の欄。入れる前に出す）：「データを確認しました。3 項目 × 3 系列、数値 7 セル」と要約し、重さの順に並べる。
  - エラー（正しいチャートを作れない＝入れられない）：空、表として読めない、数値が1つも無い、大きすぎる（2000 行・200 列まで）。
  - 要確認：読めないセル、Excel のエラー、違う種類の単位の混在、単位の有る数と無い数の混在、同じ名前の項目・列（合算しない）、1000 倍以上の外れ値、大きな表。
  - 確認（チェックで選べる。既定はおすすめの方）：表の上のタイトル・下の注記を外す、合計・小計の行と列を外す、% の列の小数（0.15 → 15%）、同じ種類の単位の混在（千円と百万円 → 多い方にそろえる）、欧州式の数（1.234,5）。
  - メモ（畳む）：空の行・列を飛ばした、セル内の改行、▲・カッコをマイナスとして読んだ、値なしの印を空欄にした、単位を読み取った（チャートの単位に入れる）。

- **「この提案は役に立ちましたか？」は、Story の時は右の一番下**。送る内容の説明（「〜確認することがあります。表のデータは含みません。」）は「i」を押した時だけ出す（1枚の時も同じ）。
- **後で議論（Story の一連の実装の後）**：提案の評価（👍／👎・理由・コメント）で何が保存され、将来の推薦の規則にどう生かすか。

## 2026-10-01（ストーリー：日本語の画面と「まずは1枚だけ作る」）

- **日本語の画面では「Story」「Main Story」「Appendix」「Question」を「ストーリー」「メインストーリー」「付録」「問い」に**（Supporting Evidence は「補足資料」）。英語の画面はそのまま。製品名の「Story Coach」は変えない。
- **右（決める場所）**：「メインストーリー：n枚」［スライド作成を始める］、データは編集画面でスライドごとに入力できること。区切りの下に、しっかりしたボタン［まずは1枚だけ作る］と「次の画面で、どの問いを1枚にするか選びます」。
- **「まずは1枚だけ作る」の流れ**（指示書 4.2：中心の問いを一つ提案し、切り替えられる）：① どの問いを1枚にするか選ぶ（Coach が、最初の相談の目的に合う問いを初期選択。示すことがある問いだけ）→ ② その問いの料理（伝えたいこと）で1枚の提案（伝えたいことは変えられる）→ ③「ストーリーに戻る」で、整えた問いのまま元の画面へ（問いは消さない）。左に「1枚にする問い」と「問いを選び直す」。
- **相談から入った時は、1枚の時も3列**：右に［このスライドから始める］、ストーリーに戻る／ストーリーとして組み立てる、「提案が意図と違う時は」、「この提案は役に立ちましたか？」。目的・チャートから入った時はこれまでどおり2列。
- **1枚の流れで出し直した時は、出し直した後も1枚のまま**（「まずは1枚だけ作る」の後・最初から1枚・1枚の提案を見ている時）。新しい読み取りから、問いを選ばずにそのまま1枚の提案（Plus と同じ流れ）。ストーリー向きの読み取りでも、ストーリーのおすすめは出さない（右の「別の進め方 ▸ ストーリーとして組み立てる」で自分で戻れる。その時は新しい読み取りから問いを組み直す）。前のストーリーの下書きは持ち越さない。ストーリーのおすすめ画面での出し直しは、これまでどおり改めて決める。
- **不具合の直し**：「まずは1枚だけ作る」を押した時に、ストーリーの下書きを計画に残す。残していないと描くたびに読み取りから作り直され、問いの id が変わり、問いを選んでも反応しなかった。

## 2026-10-01（表で整理・言葉でまとめる MVP：比較表と結論＋3つの根拠）

- **スライドの主役になる「表・言葉の型」を、チャートに付ける表（成長率表など）とは別に登録**（`registry/storyTemplates.ts`：`STORY_TABLE_COMPARISON`・`STORY_TEXT_CONCLUSION_REASONS`）。描き方は `engine/layout/templates`、中身の形・操作・確認は `features/templates`。型を足す時はこの3か所に足す。
- **保存の形**：スライドに `view`（型。無い＝グラフ）、`content`（型ごとの中身）、`look`（型ごとの見せ方）を足す。データ（Dataset）とグラフの設定は消さないので、見せ方を行き来しても、グラフに戻すと元どおり、型に戻すと前の中身。
- **プレビューと PPT は同じ配置**：比較表は PowerPoint の表（行ごとの高さ・横線だけの罫線を足した）、結論カードは図形と文字。どちらも PPT で編集できる。空の根拠・空の欄・見本の出典は描かない（見本の文言を PPT に出さない）。
- **画面**：右の「チャート」の欄を「見せ方を選ぶ」に（グラフで伝える／表・言葉で伝える）。閉じた時は「今の見せ方：〇〇　変更」。選んだら閉じて、下にその型の見せ方（強調・表示・数値／配置・強調・表示）。中央の下は表の入力／結論と根拠の入力。左はグラフ用の Coach・注意を出さず、型の説明だけ。
- **比較表を初めて開いた時**：データを入れてあれば最新の期間を文字の表に（行が年なら最新の年の1行、行が項目なら項目を比較対象の列に）、見本のままなら空の見本（候補A〜C × 市場規模・成長率・収益性・実行難易度）。
- **数の形の単位は、初めは「項目（行）ごと」**（指示書は列単位だが、比較対象を列・比較項目を行に置く比較表では、単位が揃うのは行のため。右で「列ごと」にも切り替えられる）。% は入れた数に % を付ける（12 → 12%）。
- **強調の色は既存のアクセント色のオレンジ**（見出しの紺と区別するため）。強調した列の見出しはオレンジ、セルは薄いオレンジ＋太字。ほかはグレーにしない。
- **確認は注意として出すだけ**（出力は止めない）。「見本の見出し」は比較対象の名前（候補A など）だけを数える（市場規模などの比較項目の名前はそのまま使えるため）。「前提・留意点が見本の文言のまま」は、見本の文言を入れない作りなので確認しない。
- **ストーリー**：言葉の問い（判断など）も編集画面のスライドにし、初めは結論＋3つの根拠（結論＝それまでに書いたメッセージ）。左の地図の状態に「表」「言葉」を添える。左でメッセージだけ書く欄はやめた。PPT の枚数はグラフ・表・言葉のすべて。
- 日本語の折り返しで、行の頭に句読点・閉じかっこを置かない（スライド全体の折り返しの規則）。
- **文字の揃え（左・中央・右）を右の「表示」で選べる**（ユーザーの要望）。比較表は「自動」（数は右・短い評価の語は中央・文は左）が既定で、選ぶと本文と見出しの行がその揃えになる（比較項目の列は左のまま）。結論＋根拠はカードの中の文字（番号・見出し・説明・参照）に効き、既定は左。タイトル（結論）は他のスライドと同じく左。
- **見せ方を選ぶ欄を2つのタブに**（ユーザーの要望）：閉じた時は「見せ方：〇〇（今）」。開くと上に［グラフ］［表・言葉］のタブがあり、選んだ方の分類と型だけを出す（グラフの候補で長くなり、表・言葉が見えなくなるのを防ぐ）。初めに開くタブは今の見せ方の側。表・言葉のタブは「表で整理」「言葉でまとめる」の下に型（今は比較表、結論＋3つの根拠）を並べ、型が増えたらここに並ぶ。
- 右の「現在の見せ方」の箱はやめた（上の「見せ方：〇〇（今）」と左に同じ情報があるため）。

## 2026-10-01（KPI スコアカード）

- **`STORY_TABLE_KPI`（表で整理）**：1枚のカード＝指標名・大きな数字と単位・対象期間・比較基準と増減（指示書 9.1）。カードの作りは結論＋根拠と同じ（細いアクセントライン、同じ幅・高さ、強調はオレンジ）。4つまで1段、5つから2段（1段・2段も選べる）。7つ以上は消さずに注意。

- 実績対目標の専用の形（達成率のバー）と、KPI＋小さな推移は後回し。今は比較基準に「計画比」と書けば計画との比較として使える。

## 2026-10-01（Executive Summary）

- **`STORY_TEXT_EXECUTIVE_SUMMARY`（言葉でまとめる）**：結論はメッセージタイトル。その下に指示書 14章の5項目（全体として確認されたこと／判断を変える差・例外／重要な根拠／今回判断・確認すること／前提・範囲）を横長の段で：左に項目名、中に本文、右端に参照スライド（→ スライド 2・3）。入れていない項目は描かない。項目名は変えられるが、足したり消したりはしない。

- `executiveSummary.enabled` は「メインにそのスライドがあるか」から書き戻す（以前は印だけで1枚と数えていたが、今はスライドそのものを数える）。`evidenceSlideRefs` は項目の参照スライドの合計。

- **参照スライドは右端に出さず、注記に（ユーザーの要望）**：定型では本文の後ろに *1 を付け、下に「*1 スライド 2・3」。自由に書く時は印を付けず、下に「参照：スライド 2・3」。**初めは出さない**（右の「表示」で出せる）。

## 2026-10-01（増減付き表）

- **`STORY_TABLE_DELTA`（表で整理）**：1行＝1項目。列は 項目／今の値／比較1の値／比較1との差・率／（比較2の値／比較2との差・率）。差と率はアプリが計算する。描き方は比較表と同じ（紺の見出し・行の区切り線・強調・揃え）で、増減の文字の色と合計の行の太字だけ足した（`layoutComparisonTable` に TableExtra）。

- 並べ方：入れた順／今の値の大きい順／増減の大きい順（率だけを出している時は率、それ以外は差で並べる）。
- 初めて開いた時：年ごとのデータなら列（市場など）を項目に、今＝最新の年、比較＝比較期間かその前の年。ほかは空の見本（項目A〜C）。

## 2026-10-01（ヒートマップ型の表）

- **`STORY_TABLE_HEATMAP`（表で整理）**：比較表と同じ表で、数のセルだけ値の大きさで背景の濃さを変える。言葉のセル（高・中・低など）は塗らない。濃いセルの文字は白。

- **濃さを比べる範囲は初めは「行ごと」**（比較表では比べる項目を行に置くため。単位の違う指標を同じ物差しで比べない。CLAUDE.md の「成長率表は行ごとに正規化」と同じ考え方）。列ごと・表全体も選べる。表全体で単位の違う値を比べていれば注意。
- 色は紺の濃淡（Quiet Steel Blue の一番濃い色まで）。向きは「大きいほど濃い／小さいほど濃い／プラス・マイナス（0を白、プラスは紺、マイナスは赤）」。下に小さな凡例（5段の色と読み方）。
- 多くの項目から特徴を見つける表なので、大きさの目安は比較表より大きい（列10・行15まで）。
- 比較表と同じ表を描く関数に、セルの背景を上書きする口（TableExtra.fill）を足した。
- **ヒートマップの色を選べる（ユーザーの要望）**：紺（標準）に加えて、明るめの3つ（明るい青・青緑・明るいオレンジ）。明るい色は一番濃くても中くらいの明るさにして、濃い文字のまま読めることが多いようにした。プラス・マイナスのマイナス側は、明るい青・青緑は明るい赤、明るいオレンジは紫（オレンジと赤が近いため）。
